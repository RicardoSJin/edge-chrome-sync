# 桥同步 · Edge & Chrome

通过自己的 HTTPS WebDAV 同步两个浏览器的收藏夹、部分隐私偏好和网页字号。Manifest V3，无依赖，不需要注册账户。

## 当前状态：预发布

v1.0.2 修复了原生 fetch 调用上下文错误（Illegal invocation），并优先使用 WebDAV 独占锁保护写入，兼容忽略 If-Match 的 fnOS WebDAV。已在真实 Mac Chrome 完成 NAS 连接检测、下载与同步内容校验，并验证服务器上传、解密与冲突保护；另一台设备的 Edge 首次下载仍需验证。

- [报告问题](https://github.com/RicardoSJin/edge-chrome-sync/issues)：提供浏览器版本、插件版本、请求方法和脱敏后的错误码；不要提交密码、加密口令、Authorization 请求头或个人备份。

## 安装和首次使用

1. 解压 `edge-chrome-sync-v1.0.2.zip` 到一个长期保留的文件夹。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。
4. 点击工具栏中的“桥同步”打开设置页。在 WebDAV 上预先创建一个**专用文件夹**，填入 HTTPS 文件夹地址、账户和服务器密码。
5. 设置至少 12 个字符的**独立加密口令**，两端必须完全一致。口令不需要与服务器密码相同，建议使用密码管理器生成和保管。
6. 选择同步项目，确认首次同步规则，点击“保存配置”，在浏览器提示中允许访问所填写的 WebDAV 站点及所选设置。
7. **先在数据最完整的浏览器执行一次同步**。若目录中没有本插件文件，将上传此浏览器的数据。
8. 在另一个浏览器安装，填写相同连接信息与加密口令，然后同步。可以使用“复制配置 → 粘贴文本框 → 导入配置”迁移地址和偏好；两种密码不包含在复制内容中。

接口地址请填写实际可用的 WebDAV 对外路径，例如 `https://dav.example.com/browser-sync/`。NAS 磁盘路径不能直接当作 WebDAV 对外路径。

## 支持的内容

- 收藏夹：收藏夹栏、其他收藏夹、移动收藏夹（目标浏览器有相应目录时），包括标题、URL、文件夹层级与排序。删除也随整类快照传播。
- 隐私偏好：网络预测、错误页面建议、地址自动填充开关、信用卡自动填充开关、密码保存开关、搜索建议、Do Not Track。同步的是开关，**不是保存的密码、地址或信用卡数据**。
- 字号：默认字号、等宽字号、最小字号。
- 手动同步、5/15/30/60 分钟自动检查，收藏夹变化后约 30 秒触发自动同步。浏览器后台调度可能延迟，浏览器关闭时不运行。
- 最近 5 份本地覆盖前备份，可恢复或导出。恢复后暂停自动同步，检查无误后再手动同步。

普通扩展无法读取或统一同步全部浏览器设置。本版不支持默认搜索引擎、启动页、主题、登录密码、Cookie、浏览历史、已安装扩展和其他扩展内部配置。企业策略控制的条目以及账户与本地双份收藏夹根目录会被拒绝，以避免错误映射。

## 同步规则

- 首次连接、变更服务器地址或账户、重新启用某一同步类别时，已有云端对应类别优先；没有云端数据时上传本地。
- 后续按**收藏夹 / 隐私 / 字号三个类别**分别比较修改时间，较新的整类快照覆盖较旧的；时间相同以云端为准。**不逐条合并收藏夹**，两端离线同时修改同一类别时，一端的修改可能被覆盖，可从本地备份找回。
- 记录可收到的浏览器修改事件时间；未收到事件的变更以首次检查发现的时间为准。两端应开启系统自动校时。修改时间不能替代跨设备事务日志。
- 不会覆盖未勾选的类别。同步中检查本地是否又有变化，检测到变化则停止应用；请避免在“正在同步”时继续编辑收藏夹。
- 优先使用 WebDAV `LOCK` 独占锁：加锁后重新读取并比较云端密文与 ETag，再使用锁令牌写入，最后 `UNLOCK`。竞争锁返回 423，云端已变更返回 412。首次 LOCK 产生的空资源在写入失败时清理。锁不支持（405/501）时回退到强 ETag 与 `If-Match` / `If-None-Match`，此时服务器必须正确实现条件写入；fnOS 的条件请求不能单独保证并发安全。
- 每次下载覆盖前先创建备份；先创建新收藏夹，再删除旧条目。创建失败会尝试清理新条目；删除或设置应用中断会保留恢复标记，并禁止继续同步，直到从备份恢复。
- 本地存储配额不足会停止写入，不会绕过备份继续覆盖。大量收藏夹可能达到浏览器存储上限。
- 建议关闭 Chrome/Edge 自带收藏夹同步，避免两套同步互相修改。同步隐私和字号后，浏览器可能显示“此设置由扩展控制”；可点击“释放隐私与字号设置控制”解除。

## WebDAV 要求

### 连接故障排查（v1.0.1）

设置页新增“检测连接”：使用当前填写的地址、账户、同步密钥发起只读 `PROPFIND Depth: 0`，不需要加密口令，不保存配置或修改收藏夹，也不测试写入。收到 HTTP 207 只表明目录探测取得 WebDAV 响应，不表示文件写入或解密已通过。

错误提示现在区分：缺失站点权限、连接超时、浏览器网络错误、实际重定向、HTTP 401/403/409/412。旧版统一提示中的“重定向不被允许”只是请求策略说明，不能用来判断实际发生了重定向。浏览器通常不会向扩展披露底层 DNS/TLS/代理错误，故网络错误仍需从浏览器或系统中进一步排查。

若同一 URL 直连能收到 HTTP 响应，但经过系统/Clash 代理时 TLS 握手失败，应检查代理对此域名的规则、DNS 与出口。不要重置数据加密口令，不要忽略 HTTPS 证书验证。HTTP 401 说明已到达服务，但不能确认目标目录存在，目录需认证后检测。

从旧版升级：用新版文件覆盖**原加载目录**，保留原路径；进入扩展管理页点击“重新加载”，再重新打开设置页。不要先卸载，以免丢失本地配置和备份。仅会话保存的加密口令在重新加载后需再次填写。

- 有效 HTTPS 证书、Basic 认证（支持应用专用密码），允许文件 GET / PUT；支持 LOCK / UNLOCK 时优先使用独占锁。
- 目录需事先创建；插件不执行 MKCOL，不接受重定向，也不忽略证书错误。加锁仅涉及插件自己的同步文件。
- 本插件仅使用目录中的 `bridge-sync-v1.enc.json`，与 KISS Translator 的文件格式**不互通**，不会修改其同步文件。
- 401/403：检查账号、密码、目录权限；409：检查目录存在；412：云端发生竞争写入，再同步一次；ETag 错误：调整 WebDAV / 反向代理以支持强 ETag 和条件请求。
- 不使用网页内容脚本，不依赖网页 CORS 代理；仅在保存时请求配置站点的可选主机权限。

## 加密与口令

- Web Crypto：AES-256-GCM，PBKDF2-HMAC-SHA-256（600,000 次），每次加密使用随机 16 字节盐和 12 字节 IV。修改时间及同步内容均在密文内。
- WebDAV 密码用于服务器认证；独立加密口令只在本地派生密钥，**不随云端文件上传**。
- 口令遗失后无法读取已加密云端数据。清除本地口令只会锁定同步，不会删除云端文件，也不会重置其加密。
- 默认保存在 `chrome.storage.session`，浏览器结束会话、重新加载或禁用扩展后需要重新输入。开启“在此设备记住”后以明文保存在扩展本地存储；WebDAV 密码始终在本地保存。此方案不保护已被入侵的本机。
- 本版不提供云端口令原地轮换。直接换填不同口令会解密失败。需要换口令时，先用旧口令完成同步并导出备份，再创建新的 WebDAV 专用目录，使用新口令从本地初始化，两端一起切换。
- 本地快照和备份是明文；导出备份同样为明文。卸载扩展将丢失扩展中的本地备份，请先导出重要备份。

在源码目录运行：

```powershell
node --test tests/*.test.js
```

已验证加密/错误口令/篡改、数据校验、条件请求、首次上传与下载、本地修改上传、模拟服务器冲突、创建/删除失败后的备份恢复、会话口令清理及设置适配器。页面保存交互与视觉布局已在浏览器中以模拟数据检查。

**尚未完成另一台设备 Edge 的真实下载与往返同步验证**。自动化测试使用模拟服务器和测试数据，不访问个人收藏夹或真实服务器。安装后先用测试目录和少量测试收藏夹验证一轮，再启用自动同步。

## 构建

需要 Node.js 24；源码不需要安装 npm 依赖。Windows PowerShell 中运行 `./build.ps1`，会先运行测试，再将安装包写入 `dist/`。直接开发时也可以将仓库根目录作为已解压扩展加载。
