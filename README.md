# 桥同步 · Edge & Chrome

通过自己的 HTTPS WebDAV 同步两个浏览器的收藏夹、部分隐私偏好和网页字号。Manifest V3、无依赖，数据在本地端到端加密，不需要注册开发者账户。

## 当前状态：v1.1.0 预发布

新增两个明确的覆盖操作，并保留自动双向同步。已移除收藏夹合并入口、首次合并及其后台逻辑。

| 操作 | 数据方向 | 以哪端为准 | 备份 |
|---|---|---|---|
| **覆盖（云端）上传** | 本机 → 云端 | 本机，不比较新旧 | 覆盖前将云端所选类别的旧快照备份到本机 |
| **（从云端）覆盖本机** | 云端 → 本机 | 云端，不比较新旧 | 覆盖前备份本机当前所选类别 |
| **立即双向同步 / 自动双向同步** | 按类别决定方向 | 较新的整类快照；时间相同以云端为准 | 覆盖本机前备份 |

手动操作只影响已勾选并保存的类别。上传不会修改本机收藏夹或设置，下载不会写回云端。覆盖会删除目标端对应类别中来源端不存在的收藏夹；请在操作确认框中核对方向。

- [报告问题](https://github.com/RicardoSJin/edge-chrome-sync/issues)：提供插件和浏览器版本、请求方法及脱敏错误，不要提交凭据或个人备份。

## 安装和首次使用

1. 解压 `edge-chrome-sync-v1.1.0.zip` 到长期保留的文件夹。Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式，“加载已解压的扩展程序”选择含 `manifest.json` 的目录。
2. 点击工具栏“桥同步”。在 WebDAV 预先创建专用文件夹，填写最终 HTTPS 目录地址、账户和服务器密码，例如 `https://dav.example.com/browser-sync/`。NAS 磁盘路径不能直接作为接口地址。
3. 填写至少 12 字符的独立加密口令，两端一致；它与服务器密码分开，建议用密码管理器保管。
4. 选择同步类别，确认覆盖规则，保存配置并允许对应站点及所选隐私权限。“检测连接”只检查目录，返回 HTTP 207 不代表已验证读写或加密口令。
5. **先在数据最完整的浏览器点击“覆盖（云端）上传”**，确认上传成功。
6. 在另一个浏览器填写相同连接和口令，点击**“（从云端）覆盖本机”**。下载成功后检查收藏夹，再按需开启两端的自动双向同步。

首次连接、变更地址或账户、新增类别、从备份恢复或保留当前内容解除中断后，必须先手动选择上传或下载方向。未初始化的类别不会自动同步，也不会由“立即双向同步”猜测来源。已经勾选自动同步时，手动初始化成功后会开始定时检查。

## 从旧版升级

- 用新版文件覆盖**原加载目录**，在扩展管理页点击“重新加载”，再打开设置页；不要先卸载，以免丢失配置、备份和中断恢复点。
- 各设备都更新到 1.1.0 后再启用自动同步；仍运行旧版的设备会继续执行旧版规则。
- GitHub 插件下载器使用 Releases 模式，勾选**“包含预发布版本”**，包名规则为 `edge-chrome-sync-*.zip`。下载器更新文件后仍需在扩展管理页重新加载。
- 云端文件名与加密格式保持兼容；无需清空云端或重置口令。默认只存在会话中的口令需在扩展重载后重新填写。
- 已完成同步的旧类别保留初始化状态；旧中断标记不会自动删除，需要使用下方恢复入口。

## 支持的内容

- 收藏夹栏、其他收藏夹及移动收藏夹（目标浏览器有相应目录时）：层级、标题、URL、排序和删除，均按完整快照替换。旧快照未包含移动目录时按空目录处理。
- 七项隐私开关：网络预测、错误页面建议、地址与信用卡自动填充、密码保存、搜索建议及 Do Not Track。同步的是开关，不是保存的密码、地址或信用卡数据。
- 三项网页字号：默认字号、等宽字号及最小字号。
- 隐私和字号只覆盖源快照提供且本机可控制的设置项，未提供的设置保持本机值。目标设置受其他扩展或企业策略控制时停止覆盖。
- 自动双向同步可选 5 / 15 / 30 / 60 分钟；本机收藏夹或设置变动后约 30 秒检查。浏览器后台调度可能延迟，关闭浏览器时不运行；默认关闭。

本插件不支持默认搜索引擎、启动页、主题、登录密码、Cookie、浏览历史、已安装扩展及其他扩展的内部配置。受管理条目、无法识别的非空根目录及账户 / 本地双份根目录会被拒绝。

## 覆盖与双向同步规则

- 手动上传始终使用本机所选类别，保留云端未勾选类别。已有云端文件必须先成功解密并校验，错误口令或损坏文件不能被强行覆盖。
- 手动下载必须在云端找到**所有已选类别**；缺少文件或任一类别时整次停止，不改本机，不回退成上传。首次使用应先在来源设备上传。
- 双向同步按收藏夹 / 隐私 / 字号分别比较整类快照的修改时间。离线并发编辑同一类别时，较旧的一整类修改会被覆盖。需要以某一端为准时使用对应手动覆盖按钮。
- 修改时间取浏览器变更事件时间；未收到事件时以发现变化的时间为准。两端应自动校时；异常未来时间会被拒绝。对象字段重排不视为编辑，收藏夹数组顺序仍参与校验。
- 同步期间检查本机是否又发生变化；请避免同时编辑收藏夹。已发出的网络写入可能先于后续本机变化检查完成，报错后应检查状态再重试。
- 写云端优先使用 WebDAV `LOCK`，在锁内复查密文与 ETag，再带令牌 `PUT` 并 `UNLOCK`。锁不支持（405 / 501）时要求服务器正确实现强 ETag 条件写入。云端冲突 412、锁竞争 423 时停止，不进行无条件覆盖。
- 下载覆盖先预检、备份，再创建新收藏夹、删除旧条目并完整校验。创建失败尝试清理新条目；删除或设置写入中断时保留恢复点并阻止继续同步。
- 本地备份空间不足时停止覆盖；不跳过备份。建议关闭浏览器原生收藏夹同步，避免两套同步同时改动数据。

## 本地备份与中断恢复

“本地备份”在设置页右侧；窗口较窄时位于主表单下方。它最多保留 5 份快照，包括本机覆盖前备份和手动上传前保存的云端快照。每行均可导出或恢复。**恢复会把该备份应用到本机**，包括来源为云端的旧快照；需要恢复云端时，先检查恢复到本机的内容，再手动上传。

检测到未完成应用时，失败后设置页会立即刷新并显示标为“中断恢复点”的备份。先导出该恢复点及浏览器当前收藏夹，避免只依赖扩展内存储。

- “恢复”：用备份覆盖本机对应类别，操作前再备份当前数据，保留被恢复的原备份。
- “保留当前收藏夹并解除中断”：只适用于仅含收藏夹的恢复点。验证当前内容包含旧快照全部条目（含重复项、目录和层级），备份当前快照并保留原恢复点，再解除中断；不修改收藏夹或云端。若存在缺失、并发编辑或备份失败则停止。

恢复成功后自动同步关闭，对应类别需再次手动选择上传或下载方向。若 Windows 的收藏夹较完整，应检查保留当前内容后执行上传，再在 Mac 下载。不要通过删除存储或卸载来绕过中断保护。

## WebDAV、加密与权限

- 仅支持有效证书的 HTTPS 与 Basic 认证（可用应用专用密码），目录事先创建；不执行 MKCOL、不跟随重定向、不忽略证书错误。
- 只读写专用目录中的 `bridge-sync-v1.enc.json`，与 KISS Translator 的同步格式不互通，不会修改其同步文件。
- “检测连接”使用当前填写配置发起只读 `PROPFIND Depth: 0`，不保存配置、不需要加密口令、不测试写权限。401 / 403 检查账户和权限；404 检查目录；网络无响应需另查 DNS、代理与 TLS。
- Web Crypto：AES-256-GCM、PBKDF2-HMAC-SHA-256 600,000 次，每次使用随机盐与 IV。独立口令仅在本机派生密钥，不随云端文件上传；丢失后无法找回密文。
- 口令默认保留到浏览器会话结束，可选择在可信设备明文保存。WebDAV 密码、本地快照和备份均存在扩展本地存储，不能保护已被入侵的电脑。
- 本版不提供原地更换云端加密口令。更换前先用旧口令导出备份，再使用新的专用目录和新口令初始化所有设备。
- `storage`、`bookmarks`、`alarms`、`fontSettings` 为必需权限；字号声明兼容 Edge，只有勾选后参与同步。`privacy` 和 HTTPS 站点权限按保存配置时的选择申请。无内容脚本，不读取网页或 Cookie。
- 隐私 / 字号应用后可能显示“由扩展控制”，可点击“释放隐私与字号设置控制”解除并暂停自动同步。

导出备份为明文，请妥善保管。卸载会删除本地备份，但不删除云端密文。详细说明见 [PRIVACY.md](PRIVACY.md)。

## 验证与构建

需要 Node.js 24，无需安装 npm 依赖：

```sh
npm test
```

29 项自动化测试覆盖强制双向覆盖、只读下载、未选类别保留、空云端 / 缺类别 / 错误口令保护、旧云端备份、自动同步与删除传播、旧摘要兼容、部分设置项校验、并发冲突、备份失败、中断恢复、权限及界面按钮。测试使用模拟浏览器与服务器，不接触个人数据。

真实 Windows Edge 的新版覆盖按钮及跨设备往返仍待验收。先使用测试目录和测试收藏夹确认上传 / 下载，再处理正式数据。

Windows PowerShell 运行 `./build.ps1`，测试通过后打包至 `dist/`。源码根目录可直接加载为扩展。macOS 可将 manifest、运行文件、icons、README、PRIVACY、LICENSE 按白名单打包，ZIP 根目录应直接包含 manifest.json。
